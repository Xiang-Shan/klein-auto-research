## 3. Defects found by the live run (not in the original review)

Blocking the documented loop:

| ID | Defect | Disposition in v0.3 |
|---|---|---|
| A1 | `klein gate record` / `klein finalize` write `study_state.json` + `events.jsonl` but never commit them; the next `run-one` then refuses on a dirty tree, and no document says to commit. `klein recover` reports nothing to recover. | FIXED — gate record, finalize, and recover commit their own state writes (inside a git repo); docs teach the transaction shape |
| A2 | `summarize_results.py` output (`results_summary.md`, `progress.svg`) blocks the next `run-one` as untracked files, though status is documented as runnable "any time" | FIXED — derived views are permitted dirty by the run-worktree check and are swept into the next state commit |
| A3 | The clean-tree refusal names the precondition, never the remedy | FIXED — error text names the exact files and the fix |
| A4 | Docs say run-one "restores the last working `train.py`"; it actually restores the pre-candidate `base_commit`. A manual mid-loop commit (forced by A1/A2) can silently move that anchor to a non-keep state | FIXED — doc wording corrected; A1/A2 remove the forced manual commits that created the hazard |
| A5 | `references/defaults-and-scaffolding.md` scaffold example produces `prepared_path: data/prepared/dataset.parquet` while the prepare template writes `data/prepared/prepared.csv`; the documented example cannot pass the DATA gate | FIXED — scaffold default and docs agree |
| A6 | Default `prepared_path` is `.parquet`, but `pyarrow` is an optional extra; the documented core install cannot write it | FIXED — scaffold defaults to CSV; parquet remains available via `--prepared-path` + the `parquet` extra |
| A7 | Phase telemetry is structurally dead for v2 studies: the scaffold writes `phases[].budget_seconds`/`max_experiments`, the summarizer expects v1 `budget_h`/`experiments: {min,max}` — every v2 phase renders `n/a` | FIXED — summarizer computes v2 telemetry from run manifests against the contract's budgets |

## 4. Conclusion

The v0.2 hardening is real: every P0/P1 mechanism functions as claimed when driven live, and the review's enforceable core (transactional evidence, per-track frontiers, sealed confirmation, direction honesty) held under adversarial use. The adoption gaps are peripheral — measurement records, test coverage breadth, and first-run ergonomics — and are dispositioned above; ergonomic defects A1–A7 were the price of the review process never driving the CLI as a newcomer, and are treated as release blockers for v0.3.

# Klein Auto Research v0.1 hardening review

Review date: 2026-07-10
Hardening implementation date: 2026-07-11
Reviewed commit: `8f0ff4660a2c540bd7f45b008211595221d8d026`
Target branch: `codex/v0.2-hardening`

## Executive verdict

v0.1 has a strong research doctrine and unusually candid worked evidence, but it
is not yet a safe autonomous execution contract. The central problem is not a
modeling algorithm: key invariants are prose that the runtime does not enforce.
A newly generated study cannot call the evaluator as shipped; the canonical tee
command has no self-contained timeout/exit-code recorder; discarded candidate
code is deliberately erased; and repeated adaptive work has no sealed confirmation
split. Those gaps can turn a disciplined-looking ledger into evidence that cannot
be reconstructed or that overstates validation-set discoveries.

The right v0.2 move is to preserve the three studies as immutable v0.1 exhibits
and harden all *new* studies around a machine-readable contract, transactional
run records, track-specific frontiers, and one final-test access per track. This
keeps the useful doctrine while changing the evidence substrate beneath it.

## Ranked verified findings

### P0 — generated studies fail at their first real evaluation

The v0.1 `train-template.py` calls `kleinlib.eval.evaluate(...,
extra={"experiment": EXPERIMENT_ID})`. The evaluator requires keyword-only
`exp_id` and does not accept `extra`; it also needs `study_dir` to persist the
sidecars and snapshot. A scaffold can therefore look complete, compile, and still
raise at runtime on its first successful model fit. No executable scaffold smoke
test covered this path.

Acceptance measure: scaffold in a temporary repository, supply a minimal model
and prepared fixture, run it once, and assert a canonical metric block plus the
expected study-local artifacts.

### P0 — the canonical run instruction is not a complete crash boundary

The repeated instruction `uv run train.py 2>&1 | tee run.log` relies on the
calling shell to have `pipefail` set. A human copying only that command can receive
tee's zero status after the training process failed. The instruction mentions a
terminal timeout elsewhere but supplies neither a portable timeout mechanism nor
an automatic crash record. Buffered Python output can also disappear on a hard
crash.

Acceptance measure: one subprocess owns one run, sets `PYTHONUNBUFFERED=1`, streams
combined output, preserves every normal nonzero exit code, terminates the process
group at `max_run_seconds`, returns 124 for timeout, and writes status/exit details
to the log and immutable manifest. Tests must exercise an ordinary exit 7 and a
silent timeout.

### P0 — v0.1 destroys the exact code for negative evidence

The loop says commit a keep and revert a discard/crash; the ledger then uses `-`
for the discarded commit. Study 01 contains four useful discards whose exact
candidate configuration is consequently not reconstructable from the public
ledger. This conflicts with the doctrine that failures are where much of the
insight lives.

Acceptance measure: commit every candidate before execution; retain the candidate
commit after a discard or crash; restore only the working `train.py`; then commit
the evidence transaction. Every non-placeholder commit in the derived ledger must
resolve and its patch hash must match the run manifest.

### P0 — adaptive validation has no confirmation boundary

v0.1 fixes a train/validation split, which is better than resampling, but the same
validation fold is reused for successive ideas, early stopping, sweeps, and the
headline result. Repeated adaptation can overfit that fold without any single
experiment being obviously improper. Small improvements such as Study 00's
`+0.0014` sweep win have no uncertainty estimate or sealed confirmation set.

Acceptance measure: v0.2 declares train/development/test policy; adaptive work can
read only train/development; each track can access final test once; findings label
all pre-final numbers exploratory and final-test numbers confirmed. A small delta
without uncertainty may be reported numerically but not called real or decisive.

### P1 — one global frontier is invalid for mixed research tracks

Study 01 intentionally changes the scientific question across ranking, linear
probing, imputation repair, and anomaly ranking. A single metric column and global
keep frontier can make a lower number for a different task look like regression or
an improvement. “Keep” is meaningful only relative to a track-specific metric,
goal, minimum delta, and guardrails.

Acceptance measure: the contract declares those fields per track; the derived
v2 view includes `track`; and frontier tests interleave two tracks without either
affecting the other's incumbent.

### P1 — preflight validates files, not the declared research state

v0.1 preflight checks a non-protected branch, tree cleanliness, TSV shape, Python
syntax, and whether a prepared path exists. It warns or skips when Git is absent,
accepts any non-protected branch rather than the exact `experiments/<study-id>`
branch, does not validate gate acknowledgements or overrides, does not reject
template placeholders, and does not fingerprint prepared data or the split.
Gate state is therefore documentary rather than authoritative.

Acceptance measure: Git and the exact branch are mandatory; a v2 `study_state.json`
binds gate state, acknowledgement timestamps, override reasons, phase, artifact
hashes, and prepared-data fingerprint; any missing/changed item fails preflight.

### P1 — summary direction can silently run backward

`summarize_results.py` accepts `--goal` but otherwise guesses from tokens in the
metric column name. An unfamiliar lower-is-better name can be summarized with a
higher-is-better frontier and reversed improvement. Direction already belongs in
`study.yaml`; guessing creates a second, fallible schema.

Acceptance measure: read the configured track direction, reject a missing or
ambiguous direction, and test an unfamiliar lower-is-better metric whose values
decrease.

### P1 — the documented sweep API does not exist

The minimal sweep example constructs `SweepRunner` with `metric_name` and then
calls `record()` and `best()`. The real v0.1 constructor requires `study_dir`,
`trial_fn`, and `params_list`; its public execution method is `run()`. Copying the
sanctioned escape-hatch example therefore fails before a trial begins.

Acceptance measure: execute the Markdown example in CI against the installed
package. Sweep sidecars must validate finite metrics and JSON-serializable params,
persist exception details, resume a valid prefix, and refuse overwrite unless the
caller explicitly opts in.

### P1 — evaluator semantics are not a single validated specification

Evaluator names, computations, and optimization direction are separate strings
and code paths. Non-finite values can enter comparisons. The `metric` argument to
`evaluate_with_inner_cv` is ignored: every fold always calculates ROC AUC. The
classification guard uses an absolute `proba.std() < 0.01`, which can reject a
valid low-spread probability model and miss other near-constant pathologies.

Acceptance measure: validated metric specifications bind name, calculation, task
shape, and direction; reject NaN/inf; honor the inner-CV metric; and diagnose
near-constant finite predictions by range and unique values rather than one
absolute standard-deviation threshold.

### P1 — snapshot records are fragile and unsafe to distribute

Snapshot filenames round metrics to four decimals, so collisions can overwrite
distinct artifacts. Manifest paths can be absolute or checkout-relative in a way
that breaks after relocation. Writes are not transactional, metric identity is not
stored, missing files cannot be rebuilt or clearly reported, and model pickle
payloads are executable content.

Acceptance measure: atomic collision-proof names, relocatable manifest paths,
metric identity, SHA-256 and availability fields, explicit report/rebuild behavior,
and no committed unsafe or large pickle payloads.

### P2 — portability and performance paths have correctness debt

The E2E verifier used `e2e-smoke-$$` and deleted any branch with that name during
cleanup, whether or not the current process created it. It used BSD-only
`sed -i ''`, left the `mktemp` root behind, and synced without `--locked`.
Preprocessors use lambdas/nested callables that impede joblib round trips, hashing
is forced dense by the `ColumnTransformer` threshold, native categorical dtype can
be lost, and target encoding is hard-coded binary. Torch epoch loss averages batch
means without weighting the short final batch, moves complete arrays to the
accelerator, and keeps the best state device-resident. These are concrete defects,
but they rank below evidence integrity.

Acceptance measure: collision-injection and cleanup tests on macOS/Linux; joblib
round trips for every encoder; sparse hashing; categorical dtype preservation;
regression target encoding; sample-weighted epoch loss; streamed accelerator
batches; CPU best-state retention. Performance changes require benchmark evidence
for threshold metrics, preprocessing reuse, and lazy imports before acceptance.

### P2 — release metadata and chronology are inconsistent

The v0.1 package/CFF versions and license packaging were not ready for a hardened
0.2 wheel. The MIT license contained a dataset appendix instead of remaining the
standard license text, no central third-party or security policy existed, and the
README claimed an August 2026 sharing event while the reviewed current date was
July 2026.

Acceptance measure: package, runtime, and CFF report 0.2.0; `LICENSE` is standard
MIT; dataset notes live in `THIRD_PARTY_NOTICES.md`; `SECURITY.md` defines private
reporting and pickle boundaries; all chronology is no later than the actual date.

## Foundations to preserve

Hardening should not flatten the parts that make Klein useful:

1. The six-stage CONSULT → DATA → METHOD → EXPERIMENT/SWEEP → SYNTHESIZE →
   TUTORIAL lifecycle is clear and teachable.
2. DATA and METHOD gates explicitly resist garbage-in modeling and unexplained
   method tourism.
3. Mandatory `findings.md` and a self-contained tutorial force research to end in
   usable judgment rather than a leaderboard.
4. `program.md` is a simple, human-readable decision ledger with hypotheses and
   phase history.
5. Temporary-copy reproduction anchors are the right way to exercise committed
   study state without mutating evidence.
6. The legacy READMEs plainly disclose private-lab hashes, device dependence, and
   the limits of ancestor-campaign provenance instead of fabricating public hashes.

## Scientific limitations after hardening

v0.2 is deliberately bounded. It remains single-machine and single-run-at-a-time;
distributed scheduling is out of scope. Built-in task shapes cover binary
classification, point regression, and scalar/simulation work—not multiclass,
survival, or ranking evaluators. A single final-test access reduces adaptive bias
but does not create statistical power; uncertainty still depends on the study's
sampling design and should be reported explicitly.

The evidence base is small: three studies from one implementation day, two on the
same 58,592-row insurance dataset and one synthetic known-truth lab. Study 01's
torch rows are device-sensitive and exact regeneration is expected only on the
reference MPS setup. The bundled dataset license is the uploader's declared
Apache-2.0 license, with the verification date retained beside the data. None of
these caveats invalidates the studies, but they limit generalization.

## Measured optimization backlog

| Order | Work package | Acceptance signal | Performance budget |
|---:|---|---|---|
| 1 | Correct scaffold, safe single-run subprocess, mandatory preflight | generated study executes; exit-7 and timeout tests; exact branch/gate/hash rejection | runner overhead below 100 ms excluding child startup |
| 2 | Transactional v2 evidence and recovery | keep/discard/crash fixture; all candidate commits resolve; recovery is idempotent | manifest/event writes below 50 ms per transaction on local SSD |
| 3 | Tracks and sealed final test | interleaved-frontier and one-access tests; findings labels enforced | no extra model fit required for status/preflight |
| 4 | Metric/split/evaluator hardening | non-finite, lower-direction, inner-CV, regression/group/time split tests | split hashes stable across macOS/Linux and Python 3.11–3.14 |
| 5 | Snapshot, encoder, sweep portability | relocation/collision/joblib/sparse/resume tests | no dense conversion in hashing; atomic artifact publication |
| 6 | Torch and hot-path optimization | weighted-loss and CPU-state tests plus before/after benchmark report | accept only material median speedup with unchanged seeded outputs |
| 7 | CI and distribution | four-version core matrix, all-extras integration, ≥80% engine coverage, macOS/Windows CLI, clean wheel | core jobs under 20 min; integration under 35 min |
| 8 | Tutorial browser isolation | generated tutorial has restrictive CSP and a browser netlog with zero HTTP(S) requests | local `file://` load completes within 5 s |

The ordering is intentional: performance work cannot compensate for evidence that
is scientifically ambiguous or unreconstructable. Benchmarks should record warmup,
fixture size, platform, Python/dependency versions, median and spread; a speed claim
without that record is not an accepted v0.2 change.

## Release boundary

This hardening branch may create commits but must not publish them. No release,
push, issue, or pull request is part of the review. Acceptance requires a clean
working tree, green local and CI-equivalent tests, a fresh v2 study completing one
keep, one discard, and one crash transaction, and compatibility validation of all
three legacy studies with visible warnings.

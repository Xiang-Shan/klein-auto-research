# Defaults & scaffolding

How a study is laid out, named, budgeted, and branched. Read this before scaffolding a
study or proposing defaults.

## Study layout & naming

Every study is ONE directory: `studies/NN-slug/` — a two-digit ordinal plus a lowercase
slug (`00-known-truth-quickstart`, `03-noisy-rosenbrock-dfo`). The ordinal orders the research
narrative; the slug says what it is. One study has one coherent goal; materially
different tasks become explicit tracks with independent metric contracts/frontiers.
`klein new` scaffolds one track; add further tracks by editing `study.yaml`
afterwards — supported: state loading reconciles the per-track sealed-test map
against the current contract, so a post-scaffold track needs no hand-patching.

Scaffold it — never hand-create the tree:

```bash
uv run --locked klein new 05-my-study \
    --goal "does X beat baseline B on my data?" \
    --kind predict --modality tabular --profile generic \
    --metric val_auc --goal-direction higher \
    --data "bundled:insurance-claims" \
    --track primary [--track control:registered] [--split-seed 20260912]
```

`--kind` (seven values), `--modality` (eight), `--profile` (four shipped, or
`--profile-doc <path>`), `--audience`, repeatable `--track NAME[:MODE]`, `--split-seed`,
and `--schema-version {2,3}` (3 is the default) are the schema-3 flags; the
scaffolded entrypoint is named by kind — `train.py` (predict), `analyze.py` (estimate,
test, replicate, discover), `simulate.py` (simulate), `search.py` (optimize) — and
recorded in `entrypoint.command` / `entrypoint.mutable`. This writes the contract, program/plan (schema 3's `program.md`
opens with the `## Roster`), the rolling `playbook.md`, the schema-3 `scouting_ledger.md`,
prepare/train entrypoints, derived ledger header, auxiliary sidecar, initial
`study_state.json`, first hash-chained event, and empty artifact/run directories. It refuses to overwrite an existing study dir.
Flags fill matching placeholders; CONSULT fills the rest.

## The canonical files (fixed names)

Klein scaffolds a canonical layout — do NOT rename these to match an existing repo:

| File | Role | Mutable? |
|---|---|---|
| `study.yaml` | machine contract (tracks, metrics, split, budgets, RQs) | at CONSULT; later changes invalidate recorded fingerprints |
| `study_state.json` | gate state, hashes, acknowledgements, current phase, final-test access | generated by CLI only |
| `events.jsonl` | append-only, hash-chained lifecycle/audit events | generated by CLI only |
| `program.md` | living lab notebook (narrative, decisions, predictions) | throughout |
| `playbook.md` | rolling state of play (map, not journal; re-read before every candidate) | throughout |
| `research_plan.md` | CONSULT output (human-readable plan) | at CONSULT |
| `data_card.md` | DATA-gate output (profile + go/no-go) | at DATA gate |
| `method_card.md` | METHOD-gate output (intuition→math→impl→refs) | at METHOD gate |
| `prepare.py` | stable data prep (partitions from `kleinlib.data.contract_split`) | rare, deliberate |
| the entrypoint (`train.py` / `analyze.py` / `simulate.py` / `search.py`) and every file in `entrypoint.mutable` | THE per-experiment surface | every experiment (one idea per candidate) |
| `verify.py` (when `tracks.<id>.verifier` is declared) | the checker — never in `mutable[]`, hashed at METHOD | never after E0001 |
| `references.yaml` | the citations `ref:<key>` resolves to | at METHOD; grows |
| `scouting_ledger.md` | what was looked at before CONSULT | before the consult gate — schema 3 hashes it into the consult record, so later edits need a gate re-record |
| `claims.lock` | the numbers and claims ledger (`references/claims-protocol.md`) | generated by `klein claims` |
| `referee_report.md` | REFEREE output (Gate 3) | by the referee only |
| `verify_receipt.json` | the last `klein verify` receipt | generated by CLI only |
| `runs/E####/manifest.json` | immutable candidate/run/evidence record | generated transactionally |
| `results.tsv` | track-aware view derived from manifests (schema = kleinlib/schema.py) | generated; never hand-edit in v2 |
| `aux_metrics.tsv` | everything-not-the-primary-metric sidecar | append-only |
| `findings.md` | SYNTHESIZE output (7 sections) | at SYNTHESIZE |
| `report/index.html` | TUTORIAL output (self-contained) | at TUTORIAL |
| `generation/manifest.yaml` | the generation layer's opt-in (schema 3, OPT-IN — `references/generation-protocol.md`) | written once by `klein generation init`, before Gate 0; immutable |
| `generation/events.jsonl` | the generation layer's own append-only hash chain (opt-in) | generated by CLI only |
| `generation/objects/` | write-once object store, `<sha256>.json` (opt-in) | generated by CLI only |
| `generation/verify_receipt.json` | the last `klein generation verify` receipt (opt-in) | generated by CLI only |
| `generation/label.json` | the dual-pass `generation-verified` label (opt-in) | generated by `klein generation label` |

The `generation/`-, `slates/`- and `premortem/`-prefixed rows are OPT-IN and schema-3 only:
`klein new` scaffolds none of them, and a study without `generation/manifest.yaml` is
untouched by every rule in `references/generation-protocol.md`. `domain_card.md`,
`evidence_design.yaml` and `escalation_plan.yaml` are the opt-in artifacts that live at
the study root because they are meant to be READ; `knowledge/references/` is the one that lives outside the
study entirely, because a reference is a fact about the literature rather than about
one study; `slates/` and `generation/tables/` appear only once a study declares the
`slates` capability, and `premortem/` only once it declares `premortem` as well.
<!-- WP-04 -->
`parity.yaml`, `lib/parity_score.py`, `tables/parity_units.tsv` and `ai_value.jsonl`
appear the same way, once a study declares `parity` or `contribution` — the first two
at the study root because the criteria and the checker are meant to be READ, and
`lib/parity_score.py` deliberately outside `entrypoint.mutable`.
<!-- end WP-04 -->
<!-- WP-08 -->
`knowledge/objects/` and `knowledge/events.jsonl` live outside the study for the same
reason `knowledge/references/` does — knowledge is not a fact about one study — and the
markdown already under `knowledge/` is never rewritten by any verb.
<!-- end WP-08 -->
<!-- WP-06 -->
`discovery_cells.yaml` with `tables/` appear only once a study declares `surprise`.
<!-- end WP-06 -->
<!-- WP-05 -->
The `benchmark`-prefixed rows and `submissions/` belong to the CUSTODIAN study alone
(`references/planted-truth-protocol.md`); a participant's `discover` study declares no
`benchmark` capability and scaffolds none of them. `lib/score_submissions.py` sits
outside `entrypoint.mutable` for the same reason `lib/parity_score.py` does — the
checker is never the searcher.
<!-- end WP-05 -->

`data_card.md`, `method_card.md` and `referee_report.md` are NOT scaffolded by
`klein new` — they are the outputs of the DATA, METHOD and REFEREE gates, authored
from `assets/*-template.md`. `scouting_ledger.md` IS scaffolded (schema 3), so that
the consult gate's hash of it is the norm rather than the exception; a study that
scouted nothing may delete it, and the gate records `scouting_ledger: absent`.

The scaffolded entrypoint refuses to run outside `klein run-one` except in smoke
mode: `KLEIN_SMOKE=1 python <entrypoint>` executes the full path but the evaluators
skip every sidecar/snapshot write — the sanctioned pre-run syntax check. A sealed run
is rehearsed with `klein run-one --final-test --dry-run`, which spends nothing.

### Adopting an existing (foreign) repo

If a repo already has prep/train scripts, prefer them over renaming. Discovery hints:
prep → `prepare.py`, `scripts/prepare.py`, `download*.py`, `*kaggle*.py`; train →
`train.py`, `scripts/train.py`, `fit.py`, `main.py`. Point `study.yaml` at the real
paths and keep the loop contract.

## Split contract

The split in `study.yaml:data.split` is FIXED for the life of the study and fingerprinted
at the DATA gate. Canonical v2 policy is a safe three-way train/development/test split,
using explicit stratified, random, group, or time semantics as appropriate. Adaptive
work may use train/development only; never resample it or peek at test. Each track gets
one sealed final-test evaluation after selection. `kleinlib.data` owns the split so
every experiment sees identical membership. Legacy v1 wrappers remain readable.

## Default budgets — by run-cost class, never by row count

Starting `max_run_seconds` values when scaffolding (phase total budget and
`max_experiments` are configured independently); each profile carries its own table
(`references/profiles/<profile>.md` §6). The generic one:

| Run-cost class | Starting `max_run_seconds` |
|---|---|
| sub-second cells (analytic, small tables, exact verifiers) | 60 |
| seconds (sklearn on ≤100k rows, small simulations) | 300 |
| minutes (GBDT sweeps, medium simulations, small nets on CPU) | 1 800 |
| hours (deep nets, large simulations, cluster jobs) | set explicitly; budget in steps or tokens, `wall_seconds` informational |

After the baseline runs, tighten to `max(3× baseline wall-clock, 60s)`. A run over
`max_run_seconds` is recorded as a timeout crash. Reaching phase seconds or experiment
count pauses the study for acknowledgement. User-supplied budgets always win.

For long overnight sessions on macOS, keep the machine awake with the stdlib tool —
`caffeinate -i uv run --locked klein run-one ...` — rather than any custom helper.

## Branch rule

Studies run on `experiments/<study-slug>` — NEVER on `main`. Branch before the first
experiment:

```bash
git switch -c experiments/05-my-study
```

`main` stays the stable baseline; merge the study branch at study end. Preflight treats
being on `main` as a failure for the loop — respect it.

## uv only

All Python runs through locked `uv run`; all deps through `uv add`. `uv sync --locked` to set up;
`--extra gbdt`, `--extra deep` for the optional stacks (dev tools are a default
dependency group — plain `uv sync --locked` installs them). If `uv` is
missing, install it first — never fall back to pip/conda (lockfile drift is
undebuggable).

## Foreign-repo bootstrap

Copy `.claude/skills/klein/` into the target repo, then install the engine — the
protocols are portable markdown, but every helper imports `kleinlib` (schema and
templates are single-sourced there): add it as a dependency (see
`assets/pyproject-study-template.toml`) and `uv sync --locked`.

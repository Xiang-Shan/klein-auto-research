Method coding advice

Here is the entire per-experiment surface of this study — the actual bytes, included by reference so this page cannot drift from the code that produced the numbers above. Read the two constants in the middle first: CANDIDATE and REFERENCE. That two-line diff is an experiment.




Four things worth stealing



    
  
  • Read the bar from the contract; never write it as a literal.
      minimum_delta is loaded from study.yaml at the top of
      main. A hardcoded bar and a hardcoded split seed are the same bug,
      and the second one already cost an earlier study a whole ledger lane measured on
      the wrong partition.
    • 
  
  • Route every partition through load_partition. It
      prints the split_fingerprint: line the notary compares against the
      fingerprint the data gate froze, so a partition that silently changed is a crash
      by design rather than a mystery. It is also what lets the sealed dry run hand
      back development rows without the entrypoint knowing anything about it.
    • 
  
  • Print the comparison; do not reconstruct it. Every run refits its
      named reference rung on the same rows and prints
      delta_vs_reference and delta_in_floors. That costs one
      cheap fit and buys a registered prediction that arithmetic can decide from a
      single printed block.
    • 
  
  • Guard the divide. The floor-relative keys are printed only when
      minimum_delta is above zero. Before Phase 0 there is no floor to
      divide by, and a prediction whose key was never printed comes back
      inconclusive rather than refuted — the honest answer, and also what
      made the pre-gate smoke check harmless.
    • 




Two things this study got wrong, kept, and wrote down



    
  
  • An undeclared artifact breaks replication.
      train.py reads data/prepared/truth.json, which the
      contract never declared, so the replication harness never copied it and the
      re-run crashed. Declare every artifact your entrypoint reads, or derive it from
      committed code. This was found by attempting a replication the
      confirmation contract did not even require — which is the argument for
      attempting one anyway.
    • 
  
  • An audit that reaches past its own reading scope writes confident, false
      sentences. The data card asserts there is no literal seed in any script
      the study owns; RANDOM_SEED = 42 is right there in the file above. It
      is a fit seed, it is harmless, and the split is contract-driven — but the
      sentence was asserted about a file the clean-room auditor states it never read.
      The card is gate-hashed, so it was not edited after the fact; the correction lives
      in the lab notebook and the findings, where an append-only record belongs.

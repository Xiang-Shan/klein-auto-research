The Data

100 rows × 7 columns: the hard pair only (50 versicolor / 50 virginica), setosa dropped because it is linearly separable from both and would make every method look perfect. Four one-decimal measurements, zero missingness, every column checked by value, not dtype. Built deterministically by prepare.py from scikit-learn 1.9.0, with a byte-identical committed fixture.

There are three irises, and the DATA gate diffed them. Fisher's printed 1936 Table I, the UCI repository file, and scikit-learn's copy are not all the same dataset. A cell-level diff against committed UCI bytes found exactly rows 35 and 38 differing — three cells, six numbers across the two sources — matching UCI's own errata note verbatim, while sklearn's DESCR states its copy follows Fisher's paper rather than UCI (the corrected copy entered scikit-learn at v0.20, 2018, changelog #11082 — an external citation from the study's citations pass, not a measurement here). Both errata rows are setosa, which the prep drops — so the known errata provably cannot touch a single row of this study. That sentence is only available because the diff ran before the first model.

The printed twins. Hard-pair rows 51 and 92 — rows 102 and 143 of the full table, both virginica — carry identical measurements (5.8, 2.7, 5.1, 1.9), the only duplicated row-content in the hard pair. The 2026-08-25 check against the full 1936 scan found the same pair printed twice in Fisher's own Table I (printed virginica rows 2 and 43): the duplication is original to the 1936 publication, not a digitization artifact — and neither Bezdek et al. (1999) nor the UCI page mentions it, in the sources we checked. Duplicate record entry versus two genuinely identical flowers is undecidable at 0.1 cm resolution, so the ruling removed the leakage mechanism instead of asserting an explanation: both rows share one group_id and always travel into the same partition. Never delete historical data on a guess; n stays 100. The counterfactual that justified the care: under a stratified split the twins straddle partitions in 16 of 20 seeds — the leak would have been the normal case.

A column that exists to crash. The prepared frame keeps sklearn's 3-class species code — a perfect proxy for the target, documented as a WARN and mitigated by naming feature columns literally in families.py. It is there on purpose: the registered crash rung (E0002) hands it to the binary evaluator to prove the guard is real, and it had to be present from the first write or the DATA fingerprint would move.

The declared split. Group-aware, seed 20260828 (the talk date — a pre-committed rule the scouting never touched; seed 42 is retired because it was scouted, sealed rows included): train 60 (33/27), development 20 (10/10), sealed test 20 at base rate 7/13. A group split is not stratified — the drifted sealed base rate is a documented consequence, and the sealed value is read against it.

The Question

In 1936, R. A. Fisher printed 150 iris flowers — four measurements each — and a closed-form rule for telling species apart. Two of his three species, versicolor and virginica, overlap: this is the hard pair, and Fisher said so in print — "there is some overlap of the distributions of I. virginica and I. versicolor, so that a certain diagnosis of these two species could not be based solely on these four measurements of a single flower taken on a plant growing wild." Ninety years later this study asks the question he declined: on his own hard pair, judged honestly, does anything beat Fisher's 1936 rule?

The study's motto, written before any run: 「让 AI 通宵做研究不难；难的是天亮之后，你敢在结论上签字。」 — "Overnight AI research is easy. The hard part is a conclusion you dare to sign the next morning."

The contenders are a 90-year ladder of method history, all pre-registered: logistic regression (Berkson 1944 / Cox 1958), k-nearest neighbours (Fix–Hodges 1951 / Cover–Hart 1967), SVM-RBF (Cortes–Vapnik 1995), and histogram gradient boosting (Friedman 2001 / sklearn 2019) — plus two LDA ablations (petal-only, sepal-only) and one rung that is designed to crash.

The real subject is the discipline that makes the answer signable: three gates before any run, a scouting ledger that discloses every number the design was shaped by, a measured floor (δ = 0.033) instead of a guessed significance bar, an append-only 9-transaction ledger where discards and crashes stay as evidence, and exactly one sealed look at 20 rows nothing was ever tuned on. On 100 flowers and a 20-row development partition, the question "which method is better" turns out to be mostly a question about which split you drew — and the protocol is what keeps that fact from choosing the winner.

The Method

The 1936 anchor, taught. You have two clouds of flowers in four-dimensional measurement space. Project every flower onto one direction — a weighted sum of the four measurements — and the problem collapses to one dimension. Fisher's criterion picks the direction as a signal-to-noise ratio: maximize the squared gap between the projected class means divided by the within-class spread along that same direction,

where the within-class scatter sums squared deviations about each class mean. Only the direction is determined, which is why any comparison against printed 1936 coefficients must be a cosine, not a difference. The consequence this study leans on: there is nothing random in it — one mean per class, one scatter matrix, one linear solve. The METHOD gate proved the ten-line from-scratch implementation and sklearn's LDA are the same object: cosine ≥ 1 − 1e-12 on all three solvers (the svd residual is one float64 ULP).

The instrument. klein's lifecycle as used here: three recorded gates before any run (CONSULT freezes the contract by hash; DATA writes the provenance and leakage audit; METHOD proves the anchor from scratch), then an append-only ledger where every candidate is committed before it executes, then one sealed look. Because a 2026-08-24 design panel had already measured this same dataset, the study adds a scouting ledger, committed before the first gate — disclosure, not blindness. Its own words: "We scouted first, and everything we scouted is on the record. The registered predictions only count for the part we did not scout." A fresh split seed buys exactly one thing, stated no wider: this partition, and therefore these 20 sealed rows, were never scored during scouting.

The floor, measured not guessed. The protocol-prescribed k-seed fit-noise sweep ran first and returned std exactly 0.0 over 5 seeds — registered in advance, because a closed-form estimator gives a seed nothing to perturb. The honest noise for a deterministic method is split noise, so the committed recipe re-draws the 80 non-sealed rows 20 times (group-aware, sealed 20 frozen out of every draw), refits every family per draw, and sets

(rounded up to 3 decimal places). klein's protocol default max(2×std, range/2) = 0.0326288 did not exceed it, so the pre-registered raise-only rule left the floor at δ = 0.033. Read δ as an actionability threshold — "the incumbent's own score wobbles this much when only the split changes", conditional on these 100 flowers. It is not a confidence interval and not a significance test; the registered estimand is a protocol-level decision claim, nothing more.

Why val_brier. The primary metric is the proper score

locked at CONSULT with the reasons written down: on a 20-row development partition AUC lives on a 101-point lattice and the anchor's scouted AUC pegged at 1.000 on 14 of 20 lottery draws — a gauge reading full scale cannot rank challengers (on the sealed rows AUC, PR-AUC and F1 all sat at 1.0 again); and kNN's scouted logloss was ~92% clipping epsilon, a machine constant, not a property of the flowers. Both are still recorded on every run as auxiliaries — evidence, never the verdict.

The Data

100 rows × 7 columns: the hard pair only (50 versicolor / 50 virginica), setosa dropped because it is linearly separable from both and would make every method look perfect. Four one-decimal measurements, zero missingness, every column checked by value, not dtype. Built deterministically by prepare.py from scikit-learn 1.9.0, with a byte-identical committed fixture.

There are three irises, and the DATA gate diffed them. Fisher's printed 1936 Table I, the UCI repository file, and scikit-learn's copy are not all the same dataset. A cell-level diff against committed UCI bytes found exactly rows 35 and 38 differing — three cells, six numbers across the two sources — matching UCI's own errata note verbatim, while sklearn's DESCR states its copy follows Fisher's paper rather than UCI (the corrected copy entered scikit-learn at v0.20, 2018, changelog #11082 — an external citation from the study's citations pass, not a measurement here). Both errata rows are setosa, which the prep drops — so the known errata provably cannot touch a single row of this study. That sentence is only available because the diff ran before the first model.

The printed twins. Hard-pair rows 51 and 92 — rows 102 and 143 of the full table, both virginica — carry identical measurements (5.8, 2.7, 5.1, 1.9), the only duplicated row-content in the hard pair. The 2026-08-25 check against the full 1936 scan found the same pair printed twice in Fisher's own Table I (printed virginica rows 2 and 43): the duplication is original to the 1936 publication, not a digitization artifact — and neither Bezdek et al. (1999) nor the UCI page mentions it, in the sources we checked. Duplicate record entry versus two genuinely identical flowers is undecidable at 0.1 cm resolution, so the ruling removed the leakage mechanism instead of asserting an explanation: both rows share one group_id and always travel into the same partition. Never delete historical data on a guess; n stays 100. The counterfactual that justified the care: under a stratified split the twins straddle partitions in 16 of 20 seeds — the leak would have been the normal case.

A column that exists to crash. The prepared frame keeps sklearn's 3-class species code — a perfect proxy for the target, documented as a WARN and mitigated by naming feature columns literally in families.py. It is there on purpose: the registered crash rung (E0002) hands it to the binary evaluator to prove the guard is real, and it had to be present from the first write or the DATA fingerprint would move.

The declared split. Group-aware, seed 20260828 (the talk date — a pre-committed rule the scouting never touched; seed 42 is retired because it was scouted, sealed rows included): train 60 (33/27), development 20 (10/10), sealed test 20 at base rate 7/13. A group split is not stratified — the drifted sealed base rate is a documented consequence, and the sealed value is read against it.

Metrology before combat. E0001 anchored the frontier at 0.026744. The k-seed sweep then returned five identical values to twelve decimals — std exactly 0, as registered: 1936 has no random seed, and a closed form gives a seed nothing to perturb. Then the split lottery's first attempt crashed all 140 trials: the registered draw seeds 20260828001..020 exceed numpy's bound (ValueError: Seed must be between 0 and 2**32 - 1). The crashed sidecar is preserved beside the good one, and the fix — base + draw instead of base × 1000 + draw — was committed before any floor was stated. A registered seed scheme is code, and code can be wrong in the ordinary way. The re-run measured anchor mean 0.0187138, std 0.0163144 across 20 draws → δ = 0.033.

Coding Advice

  1. Measure the floor before the first comparison — and measure the right kind of noise [C12]. The protocol's k-seed sweep returned std exactly 0 here (five seeds, five identical values to twelve decimals: a closed form has nothing for a seed to perturb); pasting that zero into the contract would have made every difference a keep. The honest floor for a deterministic estimator is split noise: 20 group-aware re-draws gave δ = 0.033 — 1.2× the anchor's own score. Run the degenerate sweep anyway and commit it: the zero is the finding that tells you which floor you actually need.
  2. Pre-register WHICH quantity decides, then report both [C13]. RQ2's declared-split delta (1.29×δ) and lottery mean (0.71×δ, 13/20 inside ±δ) are both true and support opposite verdicts. The only thing that keeps the verdict honest is that the contract named the declared-split delta before measurement. Report only the number that agrees with your prior and you have not made a measurement — you have made a choice.
  3. Put a falsifiable positive control on the ladder, sized to fail [C14]. "No keep earned" is indistinguishable from a dead instrument unless something scored the same way is supposed to break and does. Sepal-only LDA degraded by 4.31×δ against a pre-registered 2×δ bar, with the failure branch written down in advance. Cost: one run, 0.0098 s. There is no cheaper insurance in an experimental protocol.
  4. Register crash rungs [C18]. E0002 deliberately handed the evaluator a target it must refuse and produced exit 1, disposition crash, and the registered sentence verbatim (requires target labels exactly {0, 1}; got [1, 2]). One transaction proves the guard is load-bearing rather than decorative — and it is the reason the perfect-proxy species column could be kept, documented and mitigated, instead of deleted and the guard left untested.
  5. Keep seed schemes inside the numeric domain of the library that consumes them [C19]. A date-shaped base times 1000 overflows numpy's seed bound and took down all 140 lottery trials: 
    # registered: base * 1000 + draw  -> 20260828001  (> 2**32 - 1: every trial crashed)
# committed fix, before any floor was stated:
seed = DRAW_SEED_BASE + draw      # 20260829 .. 20260848
    Prefer base + draw or a recorded SeedSequence. When a registered detail must change, change it before any statistic is stated, commit the crashed evidence beside the good run, and say so in the script header — that is what makes "we fixed a seed" verifiable rather than asserted.
  6. Make every downstream number trace to one locked file. This study's claims.lock carries its own law: "deck numbers.py reads ONLY this file; any deck/script number not traceable here fails the build." Slides, scripts and this tutorial all inherit the ledger's numbers instead of re-deriving them — a retype is a fork, and forks drift.

The winning train.py, verbatim

The exact bytes behind both the anchor (E0001) and the sealed confirmation (E0009) — included by reference at build time. Note the two disciplines it encodes: the family registry is the only way to select a model (so species and group_id can never leak in), and the sealed partition is reachable only through an explicit evaluation_kind:

"""The only per-candidate mutable surface in a Klein v2 study.

E0001 — the anchor. Fisher 1936 LDA, all four measurements, fit on train only.
Registered role (program.md ladder row 1): sets the frontier and the floor's subject.
Candidate selection happens ONLY through FAMILY (families.py registry); feature
columns come from the registry so `species` (a perfect target proxy) and `group_id`
can never leak in (data_card WARN #1).
"""

from __future__ import annotations

import os
import time

import kleinlib
from kleinlib.data import load_prepared, three_way_split

import families

#: The registered family this candidate runs. The ONE line the ladder edits.
FAMILY = "anchor_lda4"

RANDOM_SEED = 42
SMOKE = os.environ.get("KLEIN_SMOKE") == "1"
EXPERIMENT_ID = os.environ.get("KLEIN_EXPERIMENT_ID") or ("SMOKE" if SMOKE else None)
TRACK = os.environ.get("KLEIN_TRACK") or ("primary" if SMOKE else None)

PREPARED = "data/prepared/iris_hard_pair.csv"
TARGET = "is_virginica"


def load_split(evaluation_kind: str):
    """Select development or the sealed final-test partition explicitly.

    Split = study.yaml's declaration verbatim: kind group (twins iris-102/143 share
    one group id and always travel together), seed 20260828, 0.20/0.20.
    ``final_test`` fits the SAME train-only incumbent and evaluates the sealed 20 —
    the seal confirms the incumbent's LEVEL vs its development value (program.md
    predictions row: sealed within ±2×minimum_delta of dev; base rate 7/13 noted).
    """
    if evaluation_kind not in {"development", "final_test"}:
        raise RuntimeError(f"invalid KLEIN_EVALUATION_KIND={evaluation_kind!r}")
    df = load_prepared(PREPARED)
    y = df[TARGET]
    x_tr, x_dev, x_te, y_tr, y_dev, y_te = three_way_split(
        df,
        y,
        task="classification",
        strategy="group",
        development_size=0.20,
        test_size=0.20,
        seed=20260828,
        groups=df["group_id"],
    )
    columns = list(families.REGISTRY[FAMILY][1])
    if evaluation_kind == "development":
        return x_tr[columns], x_dev[columns], y_tr, y_dev
    return x_tr[columns], x_te[columns], y_tr, y_te


def build_model():
    model, _columns = families.build(FAMILY)
    return model


def main() -> None:
    t0 = time.time()
    evaluation_kind = os.environ.get("KLEIN_EVALUATION_KIND")
    if SMOKE:
        evaluation_kind = evaluation_kind or "development"
    missing = [
        name
        for name, value in (
            ("KLEIN_EVALUATION_KIND", evaluation_kind),
            ("KLEIN_EXPERIMENT_ID", EXPERIMENT_ID),
            ("KLEIN_TRACK", TRACK),
        )
        if value is None
    ]
    if missing:
        raise RuntimeError(
            "train.py must be invoked through `klein run-one`. For a pre-run "
            "syntax/shape check use `KLEIN_SMOKE=1 python train.py` — it prints "
            "the canonical block, writes no sidecars or snapshots, and is not "
            "evidence. Missing: " + ", ".join(missing)
        )
    X_tr, X_dev, y_tr, y_dev = load_split(evaluation_kind)
    model = build_model()
    fit_start = time.time()
    model.fit(X_tr, y_tr)
    fit_seconds = time.time() - fit_start
    kleinlib.eval.evaluate(
        model,
        X_dev,
        y_dev,
        exp_id=EXPERIMENT_ID,
        study_dir=".",
        t0=t0,
        fit_seconds=fit_seconds,
        train_n=len(X_tr),
        val_n=len(X_dev),
        metric_name="val_brier",
        metric_goal="lower",
    )


if __name__ == "__main__":
    main()

The Data

Source and shape. The corpus is tinyshakespeare, bundled inside the repository and re-derived by prepare.py against the packager’s published sha256 on every run — 1115394 characters, pure ASCII, a 65-character vocabulary (\n, space, punctuation, and upper- and lower-case letters). Public-domain text, packaged by karpathy/char-rnn under an MIT-declared README.

The prepared artifact is a block index, not a feature table. One row per contiguous 1024-character block, 1089 rows in total — not one row per training example. A character language model’s real target is the next character, which no column can hold, so the contract names a placeholder column (n_chars) purely so the splitter has something to drop. A generic tabular profiler reads that placeholder as a 0.09%-minority “imbalanced target”; nothing in this study ever predicts it, and the data card exists partly to say so in writing before that misreading can propagate anywhere.

The split: contiguous blocks, ordered in time

The corpus is ordered natural language, so partitions are character-offset ranges, never a shuffle — a shuffled split would let a training window straddle a boundary and read the second half of a sentence whose first half sits in a different partition.

All three are contiguous, verified by prepare.py at write time. Klein’s development fingerprint covers train + development — the first 90% of the corpus — and the sealed final tenth is opened exactly once. Every fingerprint (prepared data, split policy, both realized partitions) is frozen at the DATA gate and every run prints its own realized split_fingerprint back for the notary to compare.

The leak detector: hash the content, not the position

Each block also carries a group id: the sha256 prefix of its normalized text — casefolded, whitespace collapsed. Hashing content instead of a trivial block-position id gives the check teeth: it would fail if the same passage reappeared in two partitions under a cosmetic case or spacing difference. It found nothing to flag — every one of the 1089 blocks stays inside one partition. A second, finer-grained audit measures Jaccard similarity of character 8-grams across partitions:

The largest similarity any held-out block has to anything the model may train on is an overlap of common English 8-grams, not of content. There is nothing to memorize across the split.

Four eval-harness controls, run through the study’s own scoring path

A tabular profiler has nothing to check on an index table with no features and no real target, so the harness itself was audited by feeding it four known predictors and checking that a correct harness scores each one where theory says it must:

ControlRoleScore (nats/char)Verdict
uniformnegative — chance4.174388PASS

copy-the-inputnegative — off-by-one detector4.750043PASS

The last row is the interesting one. A predictor that bets the next character equals the current one has no business scoring near chance either way — a correct harness must score it worse than chance, because it is confidently wrong on every character where the text actually changes. If the harness aligned targets with inputs by one position instead of shifting them, that same predictor would score exactly nats, which is the classic off-by-one bug this control exists to catch. All four controls PASS, and the diagnostic rate of the model’s predicted character actually matching the one just read is 0.024523, not 1.0.

Go / no-go

No BLOCKER is open. Two WARNs are accepted and disclosed rather than fixed, because both are identical for every candidate and both are pinned by the eval_context guardrail: the fixed 128-character evaluation window handicaps the first predicted character of every window with no context at all, and the final partial window of each partition is read as context but never scored. Neither can favor one candidate over another, so both cancel in every comparison this study makes. In particular there is no literal split seed anywhere in an evaluator or entrypoint — every run asks the contract for its partition and the verifier additionally refuses any checkpoint whose recorded split fingerprint disagrees with the realized one.

Decision: GO. The corpus reproduces its published identity exactly, the partitions are contiguous ranges with no window able to straddle them, no block is a near-duplicate of anything in an earlier partition, and every eval-harness control — including the one built to catch an off-by-one bug — behaves as a correct harness must.

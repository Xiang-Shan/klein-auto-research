The Method

The model, in one paragraph. A character-level language model is a lookup table plus a mixer. Every one of the 65 characters in the vocabulary gets a 128-dimensional vector; a stack of four pre-norm transformer blocks lets each position mix in information from the positions before it — never after, which is what “causal” means; a final linear layer turns each mixed vector back into a score for each of the 65 characters. Train it to put probability on the character that actually comes next, and the loss it reports is the average surprise, in nats, of the next character given everything before it in the window.

where is the complete, non-overlapping tiling of the evaluation range into windows of characters — no sampling, no seed. A model that has learned nothing scores a uniform 4.174387 nats (); one that has learned only which characters are common scores 3.307264, an add-one unigram fitted on the train partition alone. Anything below that is the model actually using context.

The budget, in one paragraph. The honest way to compare training recipes is at matched compute, and the honest unit of compute is optimizer steps, not seconds — a step is the same amount of arithmetic on a laptop CPU and on an accelerator; a second is not. Every candidate here runs for exactly 2000 steps of 32 windows of 128 characters, and the guardrail that enforces it does not read train.py — it reads the step count back out of the saved checkpoint. That is the difference between a budget and a promise.

The verifier — the idea this study exists to demonstrate. Almost every training script in the world computes its own validation loss and prints it, and that number is then the thing everyone believes. But a training script has a thousand ways to be quietly wrong about it — an evaluation batch drawn from the training range, a target sequence never shifted, a checkpoint saved one step later than the loss was measured, a dropout mask left on at evaluation. So this study separates the searcher from the checker. train.py trains and saves a checkpoint. A second, immutable program, verify.py, then runs in its own process: it loads that checkpoint from disk, asks the contract — never the training script — which characters are the validation partition, rebuilds the model from the checkpoint’s own config with its own independent implementation of the architecture, and recomputes the loss from scratch. The checker’s number is the one the study uses. The trainer’s own estimate is recorded beside it, and if the two disagree by more than nats the run is a crash — not a result to be argued about. The person who ran the assay does not also certify the standard.

Tying removes one whole weight matrix, which sounds like a free parameter saving — and it is, at the word-level vocabularies of tens of thousands where the original result was measured, because the same matrix is most of the model and each row is seen rarely. At a 65-character vocabulary the table is tiny and every row is seen constantly, and tying forces one matrix to serve as both the input lookup and the output classifier with no logit scale to reconcile the very different norms the two roles want. Whether that mechanism holds is exactly what this study measures, in the journey section below.

Three deliberate design choices, and what each costs

  1. The checker re-implements the architecture instead of importing model.py. Cost: duplicated code, and the architecture family becomes part of the contract — a candidate that changes the module tree produces an artifact the checker cannot load, and the run crashes. Benefit: the checker cannot be edited by the search. Two implementations that agree are evidence; one implementation compared with itself is not.
  2. The evaluation is a complete tiling, not sampled batches. Cost: the first character of every window is predicted from no context at all, and the last partial window of each partition is read as context but never scored. Benefit: the trainer’s number and the checker’s number are the same deterministic quantity, so the verifier tolerance can guard float and device drift rather than hide a real disagreement inside a fit-noise-sized fudge factor.
  3. The budget is steps, not seconds. Cost: a wider model gets the same number of steps and therefore more arithmetic per step — not the compute-optimal frontier of scaling-law doctrine, which grows model size and data together. Benefit: the comparison is device-independent and reproducible on a CPU in CI.

The regime this study sits in is small on every axis: 891904 training characters, an 824320-parameter model, a 2000-step budget with a 128-character evaluation context. What that regime does to four textbook levers is the rest of this report.

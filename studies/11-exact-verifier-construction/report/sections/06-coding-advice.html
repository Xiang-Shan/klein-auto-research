6 · Search and verifier coding advice

Four lessons, each with the run that paid for it. They are the study's research-discipline claims, and they are what transfers.

§6.1 · Write the checker as the dumbest correct thing — C6

Here is the declared verifier, in full, as the bytes the METHOD gate hashed and the notary ran ten times. Read the check function: it is a sequence of refusals, then a loop over every triple.




Things worth copying:



    

  • It imports nothing from the search. lib/nothree.py is not
in its import list and never will be; that is what makes the two implementations' agreement
evidence instead of a tautology.
    • 

  • It refuses before it scores. Malformed JSON, a non-integer coordinate
(bool checked explicitly — True is an int in Python),
a point off the grid, a repeated point. Well-formedness is the checker's job too.
    • 

  • It reports the searcher's self-report rather than punishing it.
claim_excess = claimed - verified is printed as a number. Policing that
difference is the notary's job, at tolerance: 0, and that separation is why
E0008 became a crash rather than a silently-corrected score.
    • 

  • It writes no aux rows (study_dir=None). The aux sidecar is
idempotent per experiment id, so a verifier writing under the run's id would erase the
search telemetry the run had just recorded. Its own cost lands on the manifest as
verifier.wall_seconds, where it belongs.
    • 




The cost of being dumb: 26235 cross products on the largest object, 0.002046 seconds.
The benefit of being dumb is the planted control named
parabola_plus_one — twelve points containing exactly one bad triple — which a
checker that sampled triples would very likely have passed.



§6.2 · Freeze the controls before the checker meets them — C7



The twelve planted objects and the one known-valid object are written by
prepare.py into the artifact the DATA gate hashes. The gate record carries its
sha256; the file is regenerable from committed code and from nothing else.



payload = {
    "instances": {"n_small": {...}, "n_large": {...}},
    "seed_blocks": {"development": DEVELOPMENT_SEED, "sealed": SEALED_SEED},
    "budgets": BUDGETS,
    "controls": {
        "negative": {...},          # the Erdos parabola set, expected_objective = p
        "positive": {"count": 12, "objects": planted_invalid(N_SMALL)},
    },
}




It costs nothing to arrange and it removes a whole class of self-deception: a positive
control that can be softened after it fails is not a control. The same file carries the
seed blocks, which is how a study with no rows still gets a sealed access — and why no
literal seed appears in any script this study owns.



§6.3 · Give the guard a test it can fail — C8



The per-experiment mutable surface is search.py, and a candidate is a
cell: which mode, which rung of the frozen ladder. E0008's diff was three
constants.



-CELL = "unassigned"        # the cell this candidate measures
-MODE = "search"            # controls | search | overclaim
-OVERCLAIM_BY = 0           # points to add to the SEARCH's self-report, not to the object
+CELL = "overclaim-by-one"  # the cell this candidate measures
+MODE = "overclaim"         # controls | search | overclaim
+OVERCLAIM_BY = 1           # points to add to the SEARCH's self-report, not to the object




One point of inflation — the smallest lie available — and the notary refused the run at
tolerance: 0. If you ship a disagreement guard, spend one run proving it
fires; documentation that a mechanism exists is not evidence that it works.



Here is the entrypoint the notary actually executed, in full. Note that it computes no
objective that enters the ledger: it writes an object, states what it thinks that object is
worth, and prints the artifact path the verifier will be pointed at.






§6.4 · Do the headroom arithmetic before the first run — C9



When the best known value equals a proven bound, the frontier is closed before it opens,
and two divisions tell you so:






Klein discloses that at preflight and refuses development runs until the closed door is
on the record. The acknowledgement is where a study says what it is for instead:



klein headroom ack --track n_small --acknowledged-by lead-agent \
  --note "run-anyway: the door is closed by a theorem, not by a losing phase. ...
          This study is not looking for an improvement; it is looking for an object
          that ATTAINS the known maximum, and for a record of who certified it."



§6.5 · Three pitfalls this study actually hit



    

  1. Every run restores the surface, so the base state must not be a cell.
With zero keeps by construction, run-one restores search.py after
every run — to the previous candidate's exact configuration, which it would then refuse as
an unchanged re-execution. The fix is a CELL label whose base value
("unassigned") is never a cell any run uses.
    2. 

  2. An adjective is not a numeral. "Sub-millisecond" travelled from a
pre-run estimate on the data card into a locked claim, past every mechanical check, because
no scan looks at words. Re-read your qualitative claims against the logs before you lock
them. (§5.5; erratum E1.)
    3. 

  3. The budget unit can hide the thing you are comparing. Counting
addability tests is honest about cost and silent about effort: the same
2000000 tests bought 19014 greedy completions at n = 11 and 2190 at n = 31. If two
instances are to be compared, register the unit that makes them comparable.

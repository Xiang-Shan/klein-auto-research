> Protocol: `.claude/skills/klein/references/data-gate-protocol.md`.
> Modality `none`: this study reads no dataset, so the card that can catch its

## Source & shape

- **Source tag:** `synthetic:prepare.py` (resolved as printed on the
  `data source: synthetic:prepare.py -> data/prepared/instances.json` line) ·
  **Pin:** `data.sha256` not required — a `synthetic:` source is generated by a
  committed script and the gate fingerprints its output instead.
- **Modality:** `none`. There are no rows, no columns and no target column. What
  `prepare.py` writes and this gate freezes is a **problem statement**:
  `data/prepared/instances.json`, 7493 bytes of deterministic JSON containing
  - the two instances the two tracks search — `n_small` (n = 11, upper bound 22) and
    `n_large` (n = 31, upper bound 62) — each with the pigeonhole argument for its
    bound in words;
  - the two **seed blocks**: `development` = 20260903, the only block adaptive work may
    use, and `sealed` = 20260917, a block no development run may touch;
  - the registered evaluation-budget ladder: 20 000 / 200 000 / 2 000 000;
  - the verifier's two controls (below), frozen here so that they cannot be softened
    after the checker meets them.
- **Split policy:** `data.split.kind: none`. There are no rows to partition, so no
  partition fingerprint is realized and every run will print the
  `note: partition not verified` line the notary emits when neither side has a
  fingerprint. What replaces the split is the seed-block discipline above:
  `klein run-one --final-test` sets `KLEIN_EVALUATION_KIND=final_test` and `search.py`
  selects the `sealed` block by name from this hashed file.
- **Determinism:** `prepare.py` uses no randomness at all. Re-running it reproduces
  the same bytes, so the fingerprint this gate records is reproducible from the
  committed source alone.
- **Profiler used:** none applies — there is no table to profile. The audit of this
  study's evidence source is the Verifier card.

## Verifier card

### The oracle

`verify.py`, declared in `study.yaml` as
`tracks.<id>.verifier = {command: ["uv","run","--locked","python","-u","verify.py"], tolerance: 0.0, artifact_key: "solution"}`.
It is **outside `entrypoint.mutable`** (which is `["search.py"]` and nothing else), it
is hashed into `state.fingerprints.verifier` at the METHOD gate, and `klein run-one`
runs it as a second bounded subprocess with `KLEIN_ARTIFACT` pointing at the artifact
the search wrote. Its number — not the search's — is the one that enters the ledger.

**What it checks**, in this order, rejecting with exit code 2 at the first failure:

1. the artifact is readable JSON and declares `problem: "no-three-in-line"`;
2. `n` is a positive integer;
3. every entry of `points` is a `[x, y]` pair of **integers** (a `bool` is refused
   explicitly: `True` is an `int` in Python and is not a lattice coordinate);
4. every point lies on the grid, `0 <= x < n` and `0 <= y < n`;
5. no lattice point is repeated — a configuration is a set, not a multiset;
6. **no three points are collinear**: every one of the C(k,3) triples is enumerated and
   tested with the integer cross product `(b−a) × (c−a) == 0`;
7. the artifact states an integer `claimed_objective` — a searcher that will not say
   what it thinks it found cannot be audited.

**What it reports rather than punishes:** `claim_excess = claimed_objective − k`, the
searcher's self-report minus the objective computed here. Policing that difference is
the notary's job, not the checker's: `klein run-one` compares the two printed numbers
against `tolerance: 0` and raises a `verifier_disagreement` crash.

**Independence.** `verify.py` imports nothing from `lib/nothree.py` and `lib/nothree.py`
imports nothing from it. The search decides addability in O(k) by hashing normalized
directions; the checker enumerates all C(k,3) triples. Two deliberately different
algorithms agreeing is evidence; one algorithm agreeing with itself would be a
tautology.

### Exactness, cost, tolerance

| Property | Value | Why |
|---|---|---|
| `metric.exactness` | `exact` | the objective is an integer count of points, recomputed from the artifact's bytes with integer arithmetic; there is no floating point anywhere on the path |
| resolution | 1 | hence `minimum_delta: 1`; a noise floor would be meaningless, and `klein noise-floor` is never called in this study |
| `verifier.tolerance` | 0.0 | two integers either agree or they do not. A tolerance would be an invitation to round a disagreement away |
| cost per call | C(k,3) integer cross products: 165 at k = 11, 1540 at k = 22, 37 820 at k = 62 — sub-millisecond at every size this study uses | a checker has no reason to be clever; its cost is recorded on the manifest as `verifier.wall_seconds` and is never charged against the search's budget |

### Known failure modes, and what is done about each

| Failure mode | Guard |
|---|---|
| floating-point collinearity (a slope comparison that rounds) | there is no division and no float in the test; `(b−a) × (c−a)` is an exact Python integer |
| a "clever" checker that samples triples and misses one | the checker enumerates every triple; the planted control `parabola_plus_one` is 12 points with exactly **one** broken triple out of 220, which a sampling checker would probably pass |
| degenerate input: an empty or one-point configuration | vacuously valid and scored 0 or 1; that is correct, and such an object could never be a frontier result |
| a coordinate that is `True`/`False` | rejected explicitly by the `isinstance(value, bool)` test before the `int` test |
| a point off the grid, or the same point twice | rejected at steps 4 and 5; both are planted controls |
| the checker being edited to agree with the search | it is outside `entrypoint.mutable` and is hashed at the METHOD gate; `klein preflight` re-checks the hash before every run |

### The controls (frozen in `data/prepared/instances.json` at this gate)

The naming follows the protocol's detector convention: the **positive** control is the
one on which the detector is supposed to FIRE, the **negative** control is the one on
which it must stay silent.

**Positive control — twelve planted invalid objects the verifier must REJECT.** Seven
geometric defects spanning the slopes a naive checker gets wrong (0, undefined, +1, −1,
+2, +1/2, and a +2 line with unequal lattice gaps), three well-formedness defects
(a coordinate equal to n, a negative coordinate, a non-integer coordinate), one
duplicate point, and one "almost valid" object. Exercised at this gate against the
declared script:

| # | Planted object | Verifier's verdict | Message |
|---|---|---|---|
| 1 | `row_triple` | exit 2 — rejected | points (2, 5), (6, 5) and (9, 5) are collinear |
| 2 | `column_triple` | exit 2 — rejected | points (4, 0), (4, 3) and (4, 8) are collinear |
| 3 | `diagonal_triple` | exit 2 — rejected | points (0, 0), (3, 3) and (7, 7) are collinear |
| 4 | `antidiagonal_triple` | exit 2 — rejected | points (0, 8), (2, 6) and (5, 3) are collinear |
| 5 | `slope_two_triple` | exit 2 — rejected | points (0, 0), (1, 2) and (2, 4) are collinear |
| 6 | `slope_half_triple` | exit 2 — rejected | points (0, 0), (2, 1) and (4, 2) are collinear |
| 7 | `wide_triple` | exit 2 — rejected | points (0, 0), (3, 6) and (5, 10) are collinear |
| 8 | `duplicate_point` | exit 2 — rejected | the point list repeats a lattice point |
| 9 | `out_of_range_high` | exit 2 — rejected | point 2 = (11, 2) is off the 11 x 11 grid |
| 10 | `out_of_range_negative` | exit 2 — rejected | point 2 = (3, −1) is off the 11 x 11 grid |
| 11 | `non_integer_coordinate` | exit 2 — rejected | point 2 has a non-integer x coordinate 3.5 |
| 12 | `parabola_plus_one` | exit 2 — rejected | points (2, 4), (9, 4) and (0, 4) are collinear |

12 planted, 12 rejected, at this gate. **This is the audit, not the evidence.** It ran
outside a run transaction, so nothing about it is notarized; E0001 re-runs the same
battery inside a `klein run-one` transaction, and P3 (`rejected == 12`) is adjudicated
there, on a printed block, by the notary.

**Negative control — one known-valid object the verifier must ACCEPT, at a value known
in advance.** The Erdős parabola set on the 11 × 11 grid, `{(x, x² mod 11) : x = 0…10}`.
Its validity is a theorem, not a measurement: if three of its points were collinear the
integer determinant would vanish, hence vanish mod 11, and mod p that determinant
factors as (b−a)(c−a)(c−b), a unit for distinct a, b, c in [0, p). So the object is
valid and its objective is exactly 11, known before the checker runs. At this gate the
checker accepted it (exit 0) and printed `primary_metric: 11.000000`,
`triples_checked: 165.0`, `claim_excess: 0.0`. E0001 hands the same object to the
notary as its own artifact, so the negative control is performed by the notary's own
verifier invocation rather than by the search.

**A checker that fires on everything would pass the positive control and fail the
negative one; a checker that fires on nothing would do the reverse.** Both halves are
needed and both are frozen here.

### The external best-known value

Not stated on this card, deliberately. `metric.incumbent_external` quotes a published
value and this study does not put a literature number into its contract before the
METHOD gate has verified the reference that carries it; it is added by a consult
re-record, with its reason, immediately after the METHOD gate. What IS fixed here, and
is arithmetic rather than citation, is the upper bound 2n recorded against each
instance in the frozen file: three points in one row are collinear, so each of the n
rows holds at most 2 points and no configuration can exceed 2n.

**NOTE** (informational). Order most-severe first.

| 1 | NOTE | **No literal seed and no partition rule appears in any script this study owns.** `search.py` selects a seed BLOCK by name (`development` / `sealed`) from the hashed instance file according to `KLEIN_EVALUATION_KIND`; `verify.py` and `lib/nothree.py` contain no seed at all. ## Go / no-go

> **Decision:** GO
>
> **Rationale:** The evidence source of this study is an oracle, and the oracle has
> been audited in both directions before any search exists: it fired on all twelve
> frozen invalid objects and accepted the one known-valid object at exactly the value
> its theorem predicts. The objective it computes is exact, its tolerance is zero
> because two integers either agree or they do not, and it is outside the mutable
> surface and hashed at the next gate. There is no dataset, hence no leakage, no
> target contamination and no split to reproduce; the four-row checklist is N/A for
> that reason and the Verifier card is the audit that replaces it. No BLOCKER is open.

Why this section exists

The study’s conclusions are only as good as two small programs: the searcher that proposes and the verifier that judges. This section walks the executed source of both. For the searcher the page includes the exact bytes each named run executed, read from that run’s recorded candidate commit, not the file lying on disk (a registered track restores the mutable surface after every run, so the disk copy names no run). The verifier is outside the mutable surface and is shown as the declared verifier with its pinned hash.

The searcher, as executed

search.py is the study’s whole mutable surface and holds both arms, selected by the track. The four listings below are the same file included at four runs. Their provenance lines print the run id, evaluation kind, track, commit and sha256; the four hashes are identical, because the surface was never edited between runs. That identity is itself the point: the classical arm and the LLM arm ran on the same bytes, and the sealed runs ran the code the development runs ran.

Annotated walkthrough


1. One evaluation is one call of the private checker


The matched budget is only as real as its counter. Every candidate, whatever produced it, goes through _is_golomb, which spends one evaluation before it looks at the input, and a 2001st call raises. A missing entry still spends one, so malformed LLM output is not free.


def _is_golomb(marks: Any, n: int, budget: Budget) -> Verdict:
    """The searcher's private checker. Each call is one evaluation of the budget."""
    budget.spend()
    if marks is None:
        return Verdict(False, "missing", None, None, 0, ())


The counter lives in the mutable file, so the verifier cannot audit it; it only enforces that each pair spent exactly the budget. The independent record of the LLM arm’s spend is the call ledger.



2. The annealer: aim one shorter, repair, accept by repeated differences


The classical arm never searches in the space of lengths blindly. It aims one length below its best valid ruler, cuts empty cells out of the best ruler to get there, and then anneals interior marks to drive the number of repeated differences to zero. The acceptance rule is the Metropolis one (ref:kirkpatrick1983), with the energy being the count of repeated differences:


        if (
            state_verdict is None
            or verdict.repeats <= state_verdict.repeats
            or rng.random() < math.exp((state_verdict.repeats - verdict.repeats) / temperature)
        ):
            state, state_verdict = candidate, verdict
        temperature = max(SA_T_MIN, temperature * SA_COOLING)


The verdict returned by the checker carries the conflicted mark indices, and the move operator biases toward moving a mark that takes part in a repeated difference. That is the whole algorithm. It is deliberately simple, and the study’s zero for it is a statement about this annealer at 2000 evaluations. At the method-gate toy orders the same code reached the tabulated length in most trials, which is why its zero at orders 8 to 13 reads as hardness growth, not a bug.



3. The LLM arm: objects as data, never code, never repaired


The model never writes a program and the searcher never executes a model string. The prompt asks for JSON data only, the reply is parsed by a deliberately strict rule, and anything not already a valid ruler is simply an invalid evaluation:


def _parse_batch(text: str, batch: int) -> tuple[list[Any], bool]:
    """Exactly `batch` entries (None = missing) and whether the reply was one JSON list.

    The outermost [...] span is read as JSON (this strips code fences and any prose
    around it). A reply cut off mid-list falls back to every complete inner list.
    Nothing is repaired: an entry that is not already a valid ruler is an invalid
    evaluation, and a missing entry still spends its evaluation.
    """


This rule is why a fifth to three in ten of replies counted as unparsed (section 5), and why the findings recount the sealed lane from the ledger with an independent checker that reads every bracketed list generously. The strict and generous readings agree on every development best length and on every sealed zero, so the headline counts do not depend on the extraction rule.


The feedback loop is the second design choice. Each request carries the checker’s verdicts on the previous batch and the best valid length so far, and nothing else: no optimum, no table, no mention of OEIS, no lane name. One template serves both lanes, so what the model is shown does not depend on the lane.


    if previous is not None:

                  for i, (entry, verdict) in enumerate(previous, start=1)]
        lines.append(f"Best valid length so far: {best_length}." if best_length is not None

The tabulated optima are loaded by search.py for book-keeping only (the provisional count and the index of the first match). They enter no stopping rule, move, message or request. The DATA gate read every use to confirm it.



4. The one number the notary trusts is the verifier’s


main() prints a provisional optima_matched and the artifact path under solution:. The notary then runs the declared verifier on that artifact and decides on its number. In every measured run the searcher’s report equals the verifier’s. Keep that pattern: print a provisional number for the human, and let a separate script that shares no code with the searcher decide.



The verifier, as declared


verify.py is the declared verifier of both tracks. It is not in entrypoint.mutable (the checker is never the searcher), it imports nothing from search.py, and it was hashed at the METHOD gate with sha256 63a60221be1a0b66c36095c804d08799df889156c7299c1129df16f2c0bc903c, the value the data card records and the file at build matches. It is shown bare, as the current file, because a file outside the mutable surface has only one version.




What to steal from it:


    
  
  • Pin the oracle inside the hashed file. The ORACLE dictionary holds the lanes, trials, budget, batch size and OEIS lengths, and pinned_instance() refuses an instance.json that disagrees. A file the searcher can write is not an oracle.
    • 
  
  • Take the lane from the notary, not the artifact. expected_lane() maps KLEIN_EVALUATION_KIND to the lane and rejects an artifact that declares another one; a missing kind is rejected outright, so running the script by hand scores nothing.
    • 
  
  • Write the check from the definition. golomb_length builds the set of all pairwise differences with exact integers, a separate implementation from the searcher’s owner-dictionary scan. Two independent implementations disagreeing is a bug alarm; one implementation shared by both is not a check.
    • 
  
  • Refuse a contradiction. A verified ruler shorter than the table aborts the run (“the table or this checker is wrong”), which is what makes s = 1 mean “equal to” and never “beat”.
    • 
  
  • Know what it does not check. It cannot tell how a valid ruler was produced: an edit that pastes a tabulated ruler would score as a match. The defence is procedural: the committed diff, the empty-diff record on every run, replication, and the call ledger. The verifier also does not audit the searcher’s own valid-ruler and unparsed counts.
    • 




Pitfalls and war stories that bit this study


    
  
  1. A rate limit killed the first LLM cell. The ledger’s retry window (three attempts over seconds) was shorter than a per-minute provider limit, so E0002 crashed with HTTP 429 and the concurrency cap had to drop. Lesson: budget for the provider’s limit, not the happy path.
    2. 
  
  2. A dropped connection killed the second. The standard library raises a bare ConnectionResetError that the retry loop did not catch, so E0003 crashed after hundreds of paid calls. Lesson: every response read is a place for a transport error; cache every response so a rerun does not pay twice.
    3. 
  
  3. A rerun after a crash is partly the crashed run. E0004 answered a large share of its requests from the crashed runs’ shards. They are genuine responses, but only a salted re-query is an independent second draw (C12).
    4. 
  
  4. Count in orders, not only pairs. The three trials of an order sent byte-identical first requests, so every development order came out all-or-none and the exact test moved from 0.03125 to 0.5 when the unit changed (C11).
    5. 
  
  5. Declare a price block before a model-calling run. Without one, every usd reads 0, which is unrecorded, not zero (C13).
    6. 
  
  6. Keep the replica’s solution table. The salted re-query kept its call shards and metric block but not its per-pair artifact, so which pairs matched on the second draw cannot be read from the record (C14).
    7. 
  
  7. The labels were swapped between documents. The gate-hashed data card calls verifier acceptance and rejection controls the other way round from findings; the controls test the verifier only. Lesson: pick one convention before the gate hashes it.
    8. 
  
  8. A match on a tabulated object is not search. A matched-budget comparison on public answers measures recall and search together, so a claim about search needs a contamination control and a no-feedback arm before it is made (C15).
    9.

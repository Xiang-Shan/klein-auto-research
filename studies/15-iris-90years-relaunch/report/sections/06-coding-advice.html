Method coding advice

This is the actual, current mutable surface of the study — the bytes that produced E0006, the run whose configuration is still live in train.py as the modern track's incumbent (a non-selected candidate restores the surface after a run, but E0006 was selected, so nothing was restored away from it). No verifier is declared anywhere in this study: it is kind: predict, not optimize, and nothing is checkpoint-scored, so there is no checker to freeze — the fixed, unedited library code below plays that stabilizing role instead, without being described as a verifier.




Five things worth stealing



    
  
  • Keep the recipes and the printed-key shapes out of the mutable surface.
      lib/iris.py owns the five model factories, the three feature sets, both
      bootstrap helpers and the four extra={...} assembly functions
      (anchor_extra, frontier_extra, ablation_extra,
      sealed_extra), and it was complete and unedited before E0001 ran. Every
      per-experiment diff in this study is therefore “which recipe, which feature
      set, which reference” — never a new implementation smuggled in beside a
      candidate change.
    • 
  
  • Read the floor from the contract; never hardcode it.
      train.py loads minimum_delta with
      load_contract(".")["tracks"]["modern"]["metric"].get("minimum_delta") or 0.0
      on every single run. Before Phase 0 measured it, this evaluated to 0.0
      by the same idiom every other Klein study uses for an unmeasured floor — which
      is precisely how this study surfaced a MEASURED zero as a live, undistinguished
      contract state rather than crashing on a missing key.
    • 
  
  • Guard the floor-normalized keys, and let a missing key mean
      inconclusive. lib.iris.frontier_extra only adds
      delta_in_floors / gap_in_floors to the printed block when
      minimum_delta > 0:
      
    if minimum_delta and minimum_delta > 0:
    extra["delta_in_floors"] = round(
        (float(candidate_metric) - float(reference_metric)) / minimum_delta, 4
    )
    extra["gap_in_floors"] = round((float(ideal) - float(reference_metric)) / minimum_delta, 4)

    
      That single guard is why P4–P8 read inconclusive rather than
      crashing on a zero-division, and it is a direct, disclosed defensive pattern this
      study borrowed from an earlier study's own train.py.
    • 
  
  • Refit the reference inside the same cell, on the same rows. Every
      modern and ablation cell fits its candidate and
      re-fits lda_all4 in the same process, on the same
      X_fit/X_eval arrays, before computing any delta. A
      comparison assembled later from two separate log files is not paired; it is two
      numbers that happen to be near each other. That is what makes
      delta_in_floors comparable to a paired-bootstrap floor measured the same
      way at Phase 0.
    • 
  
  • Route every partition through load_partition, and read its
      printed fingerprint. It prints split_fingerprint: before
      anything else, and the notary checks that value against the one the data gate froze.
      KLEIN_SEALED_DRYRUN=1 answers a final_test request with
      development data plus a sealed_dryrun: 1 line, so
      --final-test --dry-run exercises the whole code path and spends nothing
      — the one sanctioned rehearsal, run three times in this study before any of the
      three real sealed accesses.
    • 




Pitfalls this study actually hit



    
  
  • A measured floor of exactly zero is a state your disposition rule has to
      handle, not a state that handles itself. choose_disposition's
      ordinary frontier arithmetic, primary_metric >= incumbent + minimum_delta,
      is exactly right when the floor is positive and becomes a non-strict comparison a
      tie satisfies the moment the floor is zero. If a floor can plausibly measure to zero
      on your data, decide in advance whether a tie should file as a keep, and say so on
      the record before the first run that could produce one — this study discovered
      the answer four keeps into the parade rather than one.
    • 
  
  • A duplicate row is a leakage bug even when the fix costs one row.
      The data gate's mechanized four-row audit failed unconditionally on the pre-fix
      table; the fix was a one-line DataFrame.duplicated(keep="first") call in
      prepare.py, with zero information cost and no contract edit. Run the
      check before trusting any small table, even one this well known.
    • 
  
  • The paired-bootstrap statistic for an AUC difference is not the library's
      default row-mean statistic. An AUC floor needs the SAME resampled index
      applied to the labels and to both score vectors together
      (lib.iris.paired_bootstrap_auc_delta spells this out once, rather than
      duplicating it in every sweep script), and a degenerate single-class resample has to
      be redrawn rather than allowed to make roc_auc_score undefined —
      rare at 13-versus-12 on 25 rows, but rare is exactly the class of event that should
      never crash a Phase 0 sweep at the end of a long run.
    • 
  
  • A sealed cell that also fits a development-side reference will print two
      split_fingerprint: lines. E0011 needed an in-run development
      LDA to compute its sealed_extra block, so its log prints the
      development fingerprint first and the sealed one second. The manifest still records
      the correct (sealed) fingerprint, but a check that reads the first printed
      fingerprint rather than the last would misjudge a perfectly healthy run.

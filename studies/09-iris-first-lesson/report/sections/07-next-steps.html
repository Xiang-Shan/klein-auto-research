Frictions filed against the framework

  1. Refresh the split fingerprint at the DATA gate. Scaffolding freezes that fingerprint from a placeholder seed, and the DATA gate then refreshes the prepared-data hash but not the split hash — so any study that edits its seed before the first transaction hits a preflight failure and must touch generated state by hand. Two predecessors regenerated their state wholesale; this one refreshed the single field and disclosed it. The gate should simply do it. P1.

  2. Let the noise-floor command emit its own estimand. The schema requires estimand: once a bounded metric is declared, and the tool that writes the block still cannot produce the line. It was hand-added again here. A generator that cannot emit a field its own validator demands is a trap for the next first-time user. P1.

  3. Give the sealed final-test a dry-run mode. This is the one the crash paid for. There is no way to exercise a sealed configuration's code path — build the model, resolve the columns, read the manifest — without touching a partition, so an ordinary interface defect costs the seal itself. A --final-test --dry-run that stops short of any data access would have turned E0011 into a two-second fix. P1, and the strongest case in this repository for one.

  4. Resolution is not materiality — assessed, deliberately not implemented. Every klein threshold is a measurement-resolution threshold, and no decision-value model exists anywhere in the repository, so no artifact may call clearing a floor economically meaningful. A future optional contract block with its own provenance — who priced the consequence, in what currency, dated — is sketched and stays unimplemented until a study registers one.

  5. A small one worth copying. On near-separable evaluation folds the recalibration intercept and slope are separation markers, not calibration readings: E0001 reports 16.99 and 8.27, which say the maximum-likelihood fit diverged, not that the model is badly calibrated. Any small-n study should carry that caveat in its registered auxiliary block.

Open questions for a study 10

A sealed re-check needs a new protocol, not a retry. This study's band check is unfulfilled and its seal is spent; nothing about that is repairable inside its own ledger. What a successor can do is register a new protocol — new split, new bands, its own branch sentences — and smoke the sealed configuration before the confirmation acknowledgement, which is precisely the repair the crash argues for. The unfulfilled band stays unfulfilled in the record either way.

Run the learning-curve arena where headroom actually exists. Study 08's closing suggestion survives its successor unchanged, and now with a sharper reason: across three studies on this pair, the incumbent's error and the lottery's own spread scale together at every rung, so shrinking the data fogs the game rather than opening it. The question "does a modern tabular model earn its keep when data runs out" needs a problem where the incumbent sits many floor units above zero. The motor-insurance frequency and severity studies and the hurricane return-level work are all in this repository.

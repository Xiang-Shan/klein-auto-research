The Question

Every pricing actuary has run this argument: the production rater is a GLM; the data-science team says gradient boosting prices the book better. On freMTPL2 — 678,013 French motor policies, 26,406 claims — how much better is it really, measured in the loss both models actually minimize (Poisson deviance), and with an honest error bar that says when a difference is weather rather than climate?

Three registered questions: does HGBT beat a plain GLM beyond the measured floor (RQ1)? does classical GLM feature-shaping close most of the gap (RQ2)? does native categorical handling matter versus one-hot at this cardinality (RQ3)? Priors were written down first, sourced from this repo's own knowledge cards — and one of them lost.

The Method

Claim frequency is a rate. The clean formulation both contenders share: fit on y = ClaimNb/Exposure with sample_weight = Exposure — exactly equivalent to the offset formulation, and natively supported by PoissonRegressor and HistGradientBoostingRegressor(loss="poisson"). Score with exposure-weighted mean Poisson deviance, d(y, μ) = 2(y log(y/μ) − y + μ), on a fixed development fold.

The methodological star of this study is the noise floor. It turned out to be three different numbers: the fit-seed spread of the boosted model (2σ = 0.0004), the marginal bootstrap SE of the fold's mean deviance (2×SE = 0.0108), and — the right one for a comparison — the paired-difference bootstrap SE (2×SE = 0.0018), where both models are scored on the same resampled rows so their shared shot noise cancels. The keep bar was set to the paired floor.

Coding Advice

  1. Exposure as sample_weight [C5] — frequency target, exposure weight; both sklearn Poisson implementations take it natively. No offset plumbing, no custom loss.
  2. Paired bootstrap for comparisons [C4] — resample rows once, score both fixed prediction vectors on the same draw, difference them. The marginal SE overstated comparison noise 6× here.
  3. Allowlist prepared columns [C7] — shared actuarial tables ship derived columns; this one shipped the target. Name the columns you keep, never the ones you drop.
  4. Clip predictions before deviance — μ must be > 0; np.clip(pred, 1e-6, None) or the metric raises on a confident zero.
  5. Respect the restore [F5's lesson] — after a non-keep the mutable file returns to the incumbent's state; edit from what IS there, not from what you last submitted.
